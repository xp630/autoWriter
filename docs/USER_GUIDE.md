## 1. 快速开始

### 1.1 系统要求

- **操作系统**：macOS 12+ / Windows 10+ / Ubuntu 20.04+
- **Node.js**：仅开发需要，运行时不需要
- **硬盘**：约 500 MB（应用 + 依赖）
- **网络**：需要联网调用 AI 服务

### 1.2 安装 Agent CLI

打开应用前，**先在终端确认你要用的 CLI 已安装**：

```bash
# Claude Code（推荐）
npm install -g @anthropic-ai/claude-code
claude -p "hi"   # 首次会要求登录

# pi（速度最快）
# 见 pi 官方安装文档

# opencode（开源）
curl -fsSL https://opencode.ai/install | bash

# Codex CLI
npm install -g @openai/codex
codex --version
```

> ⚠️ 至少安装**一个** CLI，否则应用启动后会提示「未检测到任何 CLI」。

### 1.3 启动应用

```bash
# 开发模式
cd autoWriter-desktop
npm install
npm run dev

# 或下载预编译包
# 双击 .dmg / .exe / .AppImage 安装
```

应用启动后默认进入**仪表盘**页面。

### 2.1 侧边栏

- **快速开始**：4 个磁贴直达核心功能
- **最近编辑**：按更新时间倒序的 5 篇文章
- **正在生成**：当有任务运行时显示队列副本

如果**首次启动**且未检测到任何 CLI，仪表盘顶部会出现引导横幅，提示去设置配置。

## 3. 写一篇文章（完整流程）

> 本节是“直接写”的老路径。如果你想先想清楚“从哪个角度写、写给谁、拿什么结果”，
> 先看 §10「内容策略与策略库」——它会插在主题输入与大纲生成之间。

### Step 1：主题 / 参考

```
┌─ 当前 Agent：[Claude Code · sonnet-4-5]    [设置] ─┐
├────────────────────────────────────────────────┤
│  ① 主题与参考                                    │
│  ┌──────────────────────────────────────────┐  │
│  │ 想写什么主题？                              │  │
│  │ 例如：Sora 对短视频行业的冲击              │  │
│  └──────────────────────────────────────────┘  │
│  🔑 3 个关键词：[Sora] [短视频] [冲击]              │
│                                                    │
│  [或粘贴参考文章 / 粘贴 URL 自动抓取]               │
│                                                    │
│                            [生成大纲 →]            │
└────────────────────────────────────────────────┘
```

**操作：**
1. 在文本框输入主题（多个关键词用逗号 / 空格分隔）
2. 输入框下方实时显示分词后的关键词 chips
3. （可选）粘贴参考文章全文到「参考文本」框，或填 URL 点「抓取」自动提取正文
4. 按 ⌘+Enter 或点「生成大纲」

> 💡 **技巧**：提供参考文章可让 AI 学习其写作框架，比纯关键词生成质量高 30%+。

### Step 2：编辑大纲

AI 生成大纲后进入此步。大纲是可编辑的 textarea，你可以：
- 修改任何条目
- 删除不想要的小节
- 合并 / 拆分段落
- 在标题前加 `[已修订]` 标记，告诉 AI「这一节我改过了，请尊重我的版本」

确认大纲无误后点「生成正文 →」。

### Step 3：正文 + 配图

正文以 Markdown 渲染显示。其中 AI 插入的配图占位符会显示为虚线框：

```
┌────────────────────────────────────┐
│  📸 点击生成配图                       │
│  深圳南山写字楼夜景                    │
└────────────────────────────────────┘
```

**操作：**
- **点占位符** → 自动 AI 生成图片并替换
- 也可点占位符旁的「图库」图标 → 从已有图库挑选
- 生成后可点击「二次润色」指令式改写（弹窗输入「让语言更犀利」等）
- 底部可复制全文 / 导出 md / docx / pdf / html / png

> 💡 **配图技巧**：占位符描述用「具体场景 + 主体 + 动作」最佳，如「程序员深夜在屏幕前写代码，蓝色调，电影感」。

```
┌─ 🤖 Agent CLI（全局）────────────────────────────┐
│  CLI 列表（绿勾=已安装）                            │
│   ☐ pi    ☑ claude  ☐ opencode  ☐ codex          │
│                                                    │
│  切换：单击 CLI 行即可设为全局默认                   │
│  检测：在终端跑 `claude -p "hi"` 验证可用           │
└────────────────────────────────────────────────┘
```

### 5.2 Model

```
┌─ 🧠 Model（针对当前 CLI）─────────────────────────┐
│  [下拉选模型]                  [🔄 拉取模型]         │
│                                                    │
│  说明：                                             │
│  • Claude Code / Codex：手动填（官方不提供 list）  │
│  • opencode：自动从 `opencode models` 拉取         │
│  • pi：手动填                                       │
└────────────────────────────────────────────────┘
```

### 5.3 图片生图设置

主开关 + 是否启用「Craft」扩写：
- ✅ 启用后，用户输入的简短描述会先经 `craft-standard.md` 通用扩写，再经 `craft-{model}.md` 模型专属优化
- ❌ 关闭后，直接用用户原文生成（节省时间但质量略低）

### 5.4 图片 Provider

```
┌─ 🖼️ 图片 Provider ─────────────────────────────────┐
│  🌐 Pollinations  ✓ 已启用  [⚙️ 配置]              │
│  🎨 Tensor.Art    ✗ 已禁用  [⚙️ 配置]              │
│  📦 Ideogram      ✗ 已禁用  [⚙️ 配置]              │
│                                                    │
│  [+ 添加 Provider]                                  │
└────────────────────────────────────────────────┘
```

- **优先级**：数字越小越优先（失败时按优先级 fallback）
- **配置项**：API Key（加密存储）、Base URL、模型列表、Provider 专属参数
- **删除**：会同时删除该 Provider 下的所有模型

### 5.5 提示词模板

实时编辑保存：
- 列出全部 `.md` 模板（outline / article / polish / craft-standard / craft-flux）
- 选中后在右侧编辑器修改，左下角显示「已保存」即生效（无需重启）
- 修改错误想恢复：手动从备份粘贴，或参考 `docs/FEATURES.md` §4 模板格式

### 5.6 数据存储

- 显示当前数据库路径、占用空间
- 「重置数据库」按钮（危险操作，需二次确认）

## 7. 提示词模板编辑

### 7.1 文件位置

模板存放在 `src/prompts/`，运行时被 Agent 加载到 system prompt：

```
src/prompts/
├── outline.md          # 大纲生成模板
├── article.md          # 正文生成模板
├── polish.md           # 二次润色模板
└── image/
    ├── craft.md        # 旧版兼容
    ├── craft-standard.md  # 通用扩写
    └── craft-flux.md      # Flux 专属优化
```

### 7.2 编辑流程

1. 进入「设置」→「提示词模板」
2. 选模板 → 编辑器中修改
3. 点「保存」→ 立即写回磁盘
4. 下次生成任务自动用新模板（无需重启）

### 7.3 模板变量

模板中可用 `{{变量名}}` 占位，运行时由 IPC handler 替换：

```markdown
# outline.md
你是 {{persona}}，为 {{channel}} 平台写作。
主题：{{keywords}}
风格：{{style}} · {{lengthDesc}}
{{referenceBlock}}
```

可用变量：`{{titleHint}}` `{{keywords}}` `{{styleDesc}}` `{{lengthDesc}}` `{{personaHint}}` `{{channelHint}}` `{{referenceBlock}}` `{{inferHint}}` `{{editWarning}}` `{{outline}}` `{{imageHint}}`

> ⚠️ 修改模板有风险，错误语法可能导致 AI 输出异常。建议先备份再改。

## 9. 常见问题

### Q1：启动后显示「未检测到任何 CLI」

**原因**：CLI 不在系统 PATH 中，或未安装。

**解决**：
1. 打开终端运行 `claude --version`（或你用的 CLI），确认能输出版本号
2. 如未安装：见 §1.2 安装对应 CLI
3. 回到应用，状态会自动更新（也可手动刷新页面）

### Q2：生成时报「CLI 启动失败」

**可能原因**：
- 未登录（某些 CLI 需要先 `claude login` 或类似流程）
- API Key 过期
- 网络问题

**解决**：
1. 在终端运行 `claude -p "hi"` 复现问题
2. 按终端中的提示登录 / 续期
3. 回到应用重试

### Q3：图片生成很慢或失败

**排查**：
- Pollinations 公共 API：偶尔限流，等待或切换到 Tensor.Art / Ideogram
- 检查 Provider 是否启用、API Key 是否正确
- 查看「设置」→「图片 Provider」中的失败提示

### Q4：数据存在哪里？

| 数据 | 位置 |
|---|---|
| 数据库 | `~/Library/Application Support/autoWriter-desktop/autoWriter.db`（macOS）<br>`%APPDATA%\autoWriter-desktop\autoWriter.db`（Windows）<br>`~/.config/autoWriter-desktop/autoWriter.db`（Linux） |
| 图片 | 同一目录下的 `uploads/` |
| 配置 | localStorage（随用户配置目录） |

### Q5：如何完全卸载？

1. 删除应用本体
2. 删除上面的 userData 目录（**会清除所有文章和图片**）
3. 可选：删除 `~/.npm-global` 中已安装的 CLI

### Q6：支持多人协作吗？

不支持。所有数据本地保存，无云同步。如需备份：
- 手动复制 userData 目录
- 或等后续版本（路线图 §10）

### Q7：生成的内容会被上传到第三方吗？

- 你的**关键词 / 大纲 / 正文 / API Key** 会发送到所选 AI 服务（Claude / OpenAI / 等），受对应服务隐私政策约束
- 你的**图片**会发送到所选图片 Provider（Pollinations / Tensor.Art / 等）
- 应用本身**不上传任何数据**到开发者服务器

### Q8：可以离线用吗？

不能。文章生成必须联网调用 AI 服务。但已生成的文章可以离线浏览 / 编辑 / 导出。

## 10. 内容策略与策略库

这一层解决的不是“怎么写”，而是“**写什么、为什么写、能不能成立**”。
完整字段含义与逐项操作见 **[docs/STRATEGY_LIBRARY.md](STRATEGY_LIBRARY.md)**，下面是必知部分。

### 10.1 两种模式

写文章页顶部二选一：

| | 借势拆解 | 命题策划 |
|---|---|---|
| 你有的 | 一篇参考文（URL 或正文） | 只是一个题目 |
| 它做的事 | 拆它的爆点，**迁移**成你的角度 | 从赛道与人群**推演**可写方向 |
| 主要风险 | 同质化 | AI 幻觉 |
| 对应抓手 | `差异锚点`（必须说清比原文多给什么） | `证据账` + `事实风险`（没备的素材强制占位） |

> 只有题目时不需要先抓参考文——选「命题策划」即可，参考文相关控件会自动隐藏。

### 10.2 标准流程

```
选题目/参考文 → 选模式 → 生成创作策略 → 从 5 个里采纳 1 条
→ 勾证据（决定能写实还是只能写观点）→ 生成大纲 → 生成正文
→ （可选）润色 → 发布 → 回策略库录战绩
```

采纳后的策略会注入**大纲、正文、润色、配图**四个环节（润色会禁改立意/角度/情绪/目标/差异）。

> “生成策略”要跑本地 Agent，实测 **30–90 秒**，面板会显示实时用时——没反应不等于失败。

### 10.3 策略库能干什么

侧栏 → 创作 → **策略库**：按模式/状态筛选、搜标题角度立意、看详情、
看它被哪些文章用过、**直接复用一条旧策略开新文章**、勾证据、录战绩、归档。

一条策略可以被多篇文章复用（公众号长文 / 小红书笔记 / 知乎回答…），
每次复用都是一条独立的执行记录与战绩。

### 10.4 证据为什么要手动勾

未勾的素材，AI 会被要求写「待补充」占位而不是编一个；勾上的才允许写进正文。
所以**先勾证据再生成正文**，你勾得越多，文章越能写实。
成立度（如 `2/3`）会同步影响“事实风险”等级与下发约束的强度。

### 10.5 战绩为什么要手动录

现阶段不自动抓平台数据。原因很实际：
**100 条真实数据胜过 10000 条推测数据。** 这些数据是后续“哪类角度在我的赛道真有效”
（策略评分与推荐）的唯一可信基础。

### 10.6 身份隔离范围

分析记录、策略、文章均按**当前身份**隔离（一台机器多人共用场景）。
升级前的历史记录对所有身份可见，不会隐身。
赛道不是隔离边界，它只是一个筛选维度。

## 附录：术语表

| 术语 | 含义 |
|---|---|
| Agent | 调用 AI 模型的 CLI 进程（Claude Code / pi / opencode / Codex） |
| Skill | 注入到 system prompt 的 markdown 文件，控制 AI 写作风格 |
| Persona | Skill 的子集，专门控制「我是谁」的写作人设 |
| Channel | Skill 的子集，专门控制「平台格式约束」（字数、emoji、风格） |
| Provider | 图片生成服务（Pollinations / Tensor.Art / Ideogram） |
| 占位符 | 正文中的 `[[配图:描述@pic1]]`，渲染为可点击生成区域 |
| Craft | 图片 prompt 的双层扩写（standard + 模型专属） |
| Queue | 任务队列，控制并发 + 串行同类 + 取消 |
| 策略 / Strategy | 一篇文章的**创作决策记录**（写给谁、表达什么、从哪切入、要什么结果）。不是大纲也不是正文 |
| 借势拆解（A） | 有参考文时的策略模式，核心能力是**迁移**，核心风险是**同质化** |
| 命题策划（B） | 只有题目时的策略模式，核心能力是**规划**，核心风险是**AI 幻觉** |
| 核心主张 / thesis | 全文要证明的那句判断（字段名 `core_point`） |
| 独特洞察 / insight | 读者带走的那一句。与主张分开：主张可以正确但毫无价值 |
| 差异锚点 / differentiator | A 模式最重要字段：本稿比原文多给什么（新立场/新证据/新人群/新场景/新结论/新经历） |
| 证据账 / evidence | 本篇要成立需要的具体素材清单，每条带 `已备 / 未备` 状态 |
| 成立度 / coverage | 已备证据 ÷ 总证据。决定正文能写实还是只能写观点 |
| 事实风险 / fact_risk | 该角度多容易让 AI 编造事实（low/medium/high），由成立度推导，决定下发约束的强度 |
| 叙事骨架 / narrative | 四拍结构模板：钩子 → 解释 → 框架 → 行动。可复用，不是一次性描述 |
| 战绩 / adoption | 一次「策略 × 文章」的执行记录，可回填阅读/点赞/收藏/评论/涨粉/主观分 |
