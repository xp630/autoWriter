# AutoWriter Season 2

**AI 时代，我们为什么还需要 DSL？**

> 开季日期：2026-09-09
> 主线形态：1 个序章 + 10 集（EP00 – EP10）
> 数据库：`seasons.id = 2`，11 行 `episodes`（status=planned，命题存 `question` 列）

---

## 一、为什么换主线

Season 1 写到中途做不下去了——**已发布 4 篇，剩下 5 集是计划位，但素材枯竭**。

原因是结构性的：**Season 1 的主角是 AutoWriter 这个工具本身**。连着 9 集都在写"我用 AI 重构写作"，而工具的建设速度追不上一集一篇的出版节奏，写到后面必然是自己解释自己。

Season 2 把主角换成**一个工程判断**：AI 都能写代码了，DSL 还有没有存在的必要？
这条线的素材来自真实开发（领域建模、写 Parser、跑 Runtime），**做得动才有得写**——这是 Season 1 学到的最重要的一条。

AutoWriter 在 Season 2 里降级成后台：它负责记观察、攒素材、排版发布，**不再是被记录的对象**。

## 二、节目单

| 集 | 标题 | 这一集要回答什么 |
|---|---|---|
| EP00（序章） | 扫盲：DSL 到底是什么？ | 建立基本认知：DSL 是什么、为什么出现、和编程语言/配置有什么区别、我们其实一直在使用哪些 DSL |
| EP01 | AI 都会写代码了，我们为什么还需要 DSL？ | 提出核心矛盾：AI 已经降低了编程语言门槛，DSL 是否反而失去了意义？先不下结论 |
| EP02 | 如果让我自己造一个 DSL，我到底想解决什么？ | 从"做语言"转向"定义问题"。明确领域、目标和 DSL 的边界 |
| EP03 | DSL 最重要的不是语法，而是领域模型 | 开始设计 Entity、Action、Rule、Workflow 等核心抽象，理解 DSL 背后的语义 |
| EP04 | 写下第一行 DSL，然后让它真正跑起来 | Lexer、Parser、AST、Validator、Runtime——从文本走向可执行系统 |
| EP05 | AI 为什么不能直接写代码？ | 主动挑战自己的假设。自然语言 → AI → Code 与 自然语言 → AI → DSL → Runtime 到底有什么区别 |
| EP06 | 我开始让 AI 写 DSL，而不是写代码 | 探索 AI 与 DSL 的新关系：AI 负责理解和生成，DSL 负责约束、验证和表达 |
| EP07 | 重新理解低代码：低代码为什么一定要"代码"？ | 从传统拖拉拽低代码，转向"领域描述 → DSL → Runtime"的新模型 |
| EP08 | AI + DSL，真的比 AI + Code 更好吗？ | 做真实对比和实验，不再讲理论，验证效率、可控性、稳定性、可维护性 |
| EP09 | 做了这么久，我终于知道 DSL 到底有没有价值 | 阶段性复盘，回答最初的问题：DSL 的价值究竟在哪里 |
| EP10 | AI 时代，我们还需要 DSL 吗？ | Season 结篇。不预设答案，让真实开发结果给出结论 |

**弧线**：EP00–01 提出问题 → EP02–04 亲手做出来 → EP05–07 三次转向（挑战自己 / 换合作关系 / 重新理解低代码）→ EP08–10 用实验收口。

## 三、这条线怎么续（Season 1 的教训写进来）

1. **先有真实进展，再写这一集**。EP04 之前必须先有能跑的 Parser，EP08 必须先有对比数据。**没有事实的一集不发**。
2. **计划位可以死，事实不能编**。11 集是路线，不是承诺；写不下去的集直接删（app 里进 EP 点「删除这集」），不硬凑。
3. **观察卡还是每天记**，但不再指望它自动长出 Season 1 那种"讲工具"的集——卡的素材要能指向 DSL/领域建模里的真实卡顿。
4. **唯一指标仍是转发**，n<20 之前不做排行榜/评分。

## 五、已登记的素材线索

### 5.1 「我设计了一个 24/7 自主运营账号的 AI，最后发现现在根本不能做」

2026-09-09 真实发生的一次设计-判掉过程，值得单独成篇：

```text
起点：想让它替我运营这个号
   ↓ 写完 Constitution / Goal / State / Action / Learning 整套设计
   ↓ 判据检查（反馈燃料、差异点、平台边界）
终点：真正不能交给 AI 的，恰恰是让我这个账号成立的东西
        —— 人的判断、经历和观点
```

**可用的反转结构**（比"我做成了"更有传播价值）：

> 我最初想：让 AI 替我运营公众号。
> 设计到最后发现：没有数据，就没有所谓的学习；没有平台能力，自主执行只是幻觉。
> 而即使两者都有——发出去的东西如果不是我的判断和我的经历，这个号就没有存在的理由。

**候选去处**（未定，等真实做完再看）：EP02「如果让我自己造一个 DSL，我到底想解决什么」/ EP07「低代码为什么一定要"代码"」——因为给 agent 定 Constitution、Action Space、State schema，本身就是一门**行为 DSL** 的设计。
