# autoWriter 产品方案（Product Plan）

> 版本：v1.1 ｜ 状态：迭代中 ｜ 作者：产品 + 工程 ｜ 更新：2026-08
> 一句话定位：**从「AI 写作工具」进化为「AI 内容理解与创作辅助工具」，最终成为「AI 内容工作室（AI Content Studio）」。**

---

## 一、产品背景与定位

### 1.1 用户真实痛点

创作者（个人 IP、自媒体、情感/科技等垂类）每天的瓶颈不是「怎么写」（How），而是「写什么」（What）与「从什么角度写」（Angle）。

工作流现状：刷小红书/公众号 → 找爆款 → 收藏 → 分析 → 定选题 → 再打开工具开写。大量时间耗在"发现与决策"，工具只覆盖了最后的"生成"。

### 1.2 产品演进路线

```
V1  AI 写作工具         输入主题 → 生成大纲 → 正文 → 配图 → 导出
V2  AI 内容理解与创作辅助 喂爆款 → AI 拆解 → 决定写不写/什么角度 → 写
V3  AI 内容工作室        发现热点 → 分析 → 选题库 → 创作角度 → 自动成文（未来）
```

**本方案覆盖 V1（已交付）+ V2（进行中）。**

## 二、核心概念模型

### 2.1 创作身份（Profile）—— 产品的地基

多人共用一台机器、或一人多垂类时，「我是谁」不应每次重设。引入 **创作身份**：

> 一个身份 = 赛道 + 人设 + 默认风格 + 默认渠道 + Agent/模型，**打包一次配好，顶栏一键切换**。

| 属性 | 说明 | 层级 |
|---|---|---|
| 赛道 track | 选题领域（情感随笔/AI与科技/社会观察…） | 🟢 身份级（设一次） |
| 人设 persona | 写作口吻/人格（IP） | 🟢 身份级（设一次） |
| 默认风格 defaultStyle | 本篇体裁的默认值 | 🟡 每篇可临时改 |
| 默认渠道 defaultChannel | 发布平台的默认值 | 🟡 每篇可临时改 |
| Agent + 模型 | 派给哪个 CLI | 🟢 身份级 |

### 2.2 四轴正交模型（关键认知）

把过去混在一起的四个概念**彻底解耦**，各自回答一个正交问题：

| 轴 | 回答 | 影响 | 层级 |
|---|---|---|---|
| **赛道 track** | 我**在哪个内容领域、给谁** | 选题角度 / 案例 / 受众 | 身份级 |
| **人设 persona** | 用**谁的口吻**说（纯语气/节奏/句式） | 文风、禁用词、情绪浓度 | 身份级 |
| **风格 style** | 这**一篇是什么体裁** | 大纲骨架（叙事/评论/科普…） | 每篇 |
| **渠道 channel** | **发在哪个平台** | 平台格式（字数/emoji/结构） | 每篇 |

> 设计红线：人设里**不得**混入选题（"擅长商业分析"这种要把赛道洗掉）；赛道**不得**混入体裁。四轴正交，组合才有意义（同一素材：情感赛道 × 故事叙述 × 温暖人设 × 小红书 ≠ 财经赛道 × 观点评论 × 冷静人设 × 知乎）。

### 2.3 赛道如何生效

赛道**直接注入大纲/正文/分析 prompt**（`buildTrackHint`）：影响选题切入角度、目标读者、案例选择。不只是一个标签。

## 三、信息架构与模块

```
侧边栏
├─ 概览      仪表盘（默认落地页）
├─ 创作      写文章 · 我的文章
├─ 素材      选题中心 · 博主源 · 图库
└─ 配置      设置（创作身份 / Agent / 图片 / 提示词 / 调度器）
顶栏右：创作身份切换器 · 任务队列徽章（含实时日志明细）
```

### 3.1 仪表盘（首页）
- 4 张 KPI：总文章 / 草稿 / 今日新增 / 累计字数
- 当前 Agent + 4 CLI 就绪状态
- 快速开始 4 磁贴
- 最近编辑 5 篇
- 正在生成（队列副本）
- 首次运行引导（未检测到 CLI 时）
- 规划中：今日热点 / 今日新增选题 / 待创作（V2 P4）

### 3.2 写文章（三步流）
Step1 主题/参考 → Step2 大纲（可编辑，[已修订] 标记）→ Step3 正文 + 配图。
- 流式生成 + 骨架 loading；生成日志看右下角队列明细
- URL 抓取（Electron 内置 Chromium + Readability）；抓取成功有反馈
- 二次润色；导出 md/docx/pdf/html/png

### 3.3 内容分析中心（V2 P0，已交付）
喂一篇参考内容 → AI 拆解成结构化 JSON → 帮用户回答"为什么火 / 要不要写 / 从什么角度写"。
- 入口：写文章页参考文区「📊 分析内容」
- 7 维分析卡：基本信息 / 主题 / 核心观点 / 爆点 / 结构 / 用户画像 / 可借鉴
- 输入：URL / 粘贴文本 / 当前参考文
- **赛道匹配护栏**（规划中，见 §6）：喂进来的内容与当前赛道不符 → 提示 + 一键拉回角度

### 3.4 我的文章
列表（筛选/搜索）+ 详情弹窗（编辑/润色/排程/发布/导出/配图）。
> **配图展示与「写文章页 Step3」用同一套组件，UI 一模一样。**

### 3.5 图库
独立图片资产库（AI 生成/上传），多文章可复用；标签/分类/尺寸检索；被引用关系可见。

### 3.6 设置
创作身份管理（多身份 CRUD + 切换）、Agent CLI/模型、图片生图设置、Provider、提示词模板、后台调度器。

## 四、配图系统（统一方案）

### 4.1 一个组件，两页共用
`<ImageSlot>` = 直观占位框（写文章页那个用户满意的样式）+ 三入口配图：

- 🎨 **AI 生成** → `generateImageFor`（走当前 provider + craft 双层扩写 + 失败 fallback）
- ⬆️ **上传本地**
- 🖼️ **从图库选**

**关键：所有配图都落 `images` + `article_images`**，写文章页配的图，去「我的文章」看同一篇天然同步、可继续换。

### 4.2 Provider 选择
「图片生图设置」选当前 provider/模型 → 配图/图库/编辑器全部尊重它。`image_providers.priority` 仅用于"失败时的备用顺序"（待与"当前 provider"进一步收敛，消除双入口歧义）。
- 已支持：Pollinations（免费）、Tensor.Art（需 Access Token）

### 4.3 复制/导出与图片
- 「复制为平台格式」：图片转 base64 内嵌；剪贴板应走 `text/html`（富文本编辑器可粘贴成真实图片）
- 预览区选区复制：配图槽的操作壳（更换/描述/提示）用 `user-select:none` 排除，正文粘贴只带干净图片

## 五、后台调度与队列

### 5.1 任务队列（agentQueue）
所有 Agent 生成（大纲/正文/润色/分析）走队列：全局并发上限、同类型串行、真实取消（SIGTERM→2s→SIGKILL）。生成日志按 taskId 归入**队列明细**，全局可见。

### 5.2 调度器（Scheduler）
主进程常驻 setInterval（60s）+ 注册式任务：`process-scheduled-articles`（到点自动发布）/ `sync-bloggers`（博主同步，抓取待接入）/ `cleanup-stale-topics`。单任务失败隔离、重入保护、可观测历史、启停可控。

```
博主源 → 抓取内容 → 爆款识别 → AI 拆解 → 评论分析 → 生成选题 → 选题中心 → 一键创作
```

| 模块 | 说明 | 状态 |
|---|---|---|
| 内容分析中心 | 单篇喂入 → 7 维拆解 | ✅ 已交付 |

## 八、交互与体验原则（本次沉淀）

1. **每个动作都要有反馈**：抓取成功 toast、AI 生成骨架/遮罩 loading、测试按钮点击必有 toast（不能灰着没反应）。
2. **长耗时任务要可见可取消**：日志进队列明细、任务可单独取消。
3. **展示即数据源**：配图在两页用同一组件，杜绝"看着一样其实两套、数据对不上"。
4. **概念正交且各就其位**：身份级（赛道/人设）设一次；每篇（风格/渠道）临时改。
5. **粘贴/导出保真**：复制为平台格式要产出干净图文（base64→text/html）。
6. **诚实反馈**：出错/未配置（如缺 token）要说清楚下一步，而不是静默。

## 十、验收标准

**内容分析（V2 P0）**：URL/文本/AI 拆解/结果保存/结果展示 全通过；用户能回答"为什么火、要不要写、什么角度"。

**配图统一**：写文章页与我的文章配图 UI 一致；任一处配的图入库并双向同步；AI 生成走当前 provider 并显示实际 provider/model。

**创作身份**：多身份切换后赛道/人设/默认值全局跟随；文章 prompt 携带赛道角度。

**总验收（北极星）**：用户每天打开产品，**5 分钟内找到今天要写什么**（V2 目标）。

---

## 十一、风险与待决

- **抓取合规/反爬**：小红书/抖音/视频号自动抓取需 cookie + worker，合规与稳定性风险 → 先手动/RSS。
- **概念收敛**：provider「当前选择」与「priority」双入口需合并成一个心智。
- **人设清洗**：现有 5 个人设描述把选题/平台焊死在里面，要洗成纯口吻才能安全升级身份级。
- **AI 稳定性**：分析输出依赖 JSON 容错 + 模型听话度；关键结论需给"依据/风险提示"。
- **多人协作**：本机单用户模型，跨设备/多人需账号体系（远期）。
